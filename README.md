# Marketing Performance in Power BI: star-schema semantic model, DAX and reconciled reporting

A Power BI report on the gold layer of my
[marketing data platform](https://github.com/GurramVardhanReddy/marketing-data-platform)
(Criteo's public attribution feed: 16,468,027 ad impressions, 435,810 conversions, 675 campaigns
over 31 days). The semantic model, DAX measures and report pages are kept as text in a Power BI
Project (PBIP: TMDL for the model, PBIR for the report), so every change is reviewable in git, and
every measure is **reconciled against SQL**: the same numbers are recomputed independently in
DuckDB and compared with what the Power BI engine returns.

## Layers

```
marketing-data-platform (dbt on DuckDB / Snowflake)
  raw.impressions            bronze   16.5M rows as delivered
  staging.stg_impressions    silver   typed, renamed, tested
  marts.*  + snapshots.*     gold     star schema + SCD type 2 spend tiers
        |  scripts/export_gold.py  (Parquet)
        v
MarketingPerformance.SemanticModel   (TMDL)   import model, star schema, 19 DAX measures
MarketingPerformance.Report          (PBIR)   3 pages, 20 visuals, generated by scripts/build_report.py
```

## Semantic model

- **Facts:** `fct_campaign_daily` (31,741 campaign-days) and `fct_conversions` (435,810 journeys).
- **Dimensions:** `dim_campaign`, `dim_date` (day and week index; the feed is anonymised, so
  there are no calendar dates and time logic is written on the day index), and
  `dim_campaign_tier_history`, the SCD type 2 history of each campaign's spend tier. A calculated
  column puts the current tier on `dim_campaign`.
- **Relationships:** both facts share the campaign and date dimensions (single direction,
  many-to-one).
- **Measures** (in a dedicated `Key Measures` table, by display folder):
  - Volume: Impressions, Clicks, Cost, Conversions, Attributed Conversions
  - Rates: CTR, Conversions per 1k Impressions, Attribution Rate, Cost per Attributed
    Conversion, Share of Cost (`ALLSELECTED`)
  - Time: Cumulative Cost, Rolling 7-Day CTR (window `FILTER` over the day index),
    Conversions WoW %
  - Campaigns: Campaign CPA Rank (`RANKX` over `ALLSELECTED`, blanks excluded), Top 10%
    Campaigns Share of Attributed Conversions (`TOPN` Pareto), Active Campaigns
  - Journeys: Conversion Journeys, Median Hours Last Click to Conversion (`MEDIANX`),
    Avg Impressions per Journey, Multi-Campaign Journey Share

## Report pages

1. **Overview:** KPI cards, daily and rolling 7-day CTR, cumulative cost, conversions by week,
   cost and attributed conversions by current spend tier.
2. **Campaigns:** spend-tier slicer, Pareto share, and a leaderboard with CTR, share of cost,
   cost per attributed conversion and CPA rank.
3. **Conversion journeys:** journeys by day, time from last click to conversion, impressions per
   journey and multi-campaign journeys, by campaign.

## Results

Numbers from the model open in Power BI Desktop (`reconciliation/dax_results.json`):

| | |
|---|---|
| Impressions / clicks | 16,468,027 / 5,947,563 (CTR 36.1%) |
| Conversions / attributed | 435,810 / 236,331 (attribution rate 54.2%) |
| Top 10% of campaigns' share of attributed conversions | 72.7% |
| Median time from last click to conversion | 20.9 hours |
| Journeys spanning more than one campaign | 0.66% |

**Reconciliation: 3,596 checks, 0 mismatches.** Totals, every campaign (cost, attributed
conversions, CPA, share of cost, CPA rank), every day (CTR, rolling 7-day CTR, cumulative cost),
every week (conversions, week-over-week change) and every spend tier match between the Power BI
engine and DuckDB SQL (`reconciliation/summary.json`). The first run caught a broken measure:
`Top` is a reserved word in DAX, so the Pareto measure's variable had to be renamed.

## Run it

1. Build the warehouse with marketing-data-platform, then export the gold layer:
   `python scripts/export_gold.py --warehouse <path>/warehouse.duckdb --out data/gold`
2. Open `MarketingPerformance.pbip` in Power BI Desktop. Set the `DataFolder` parameter
   (Transform data, Parameters) to the full path of `data/gold`, then Refresh.
3. Reconcile (Windows, with the report open):
   `powershell scripts/reconcile.ps1` then `python scripts/reconcile.py --gold data/gold`
4. After editing visuals in `scripts/build_report.py`: `python scripts/build_report.py`, and
   `python scripts/validate_report.py` checks every PBIR file against Microsoft's JSON schemas.

The data is not in the repo (the Criteo feed is CC BY-NC-SA 4.0; export it yourself).

## Limits

- Built in Power BI Desktop, not the Power BI service or Microsoft Fabric: there is no
  scheduled refresh, row-level security or deployment pipeline here.
- The feed is anonymised: `cost` is a transformed value, not currency, and there are no calendar
  dates, so standard time-intelligence functions (`DATESYTD`, `SAMEPERIODLASTYEAR`) don't apply.
- The report layout is generated from code and checked against the PBIR schemas; it opens and
  renders in Power BI Desktop, but visual formatting is deliberately basic.
